## 3. TRAPS — all cost a debugging cycle, do not repeat
1. **`sed`/`str.replace` patching FAILS SILENTLY.** An earlier sed rewrote `if n>1]`→`if n>=1]`, so a
   later replace never matched and recency ordering was never applied to FILES — invalidating a whole
   results arm. **Rewrite whole functions; never patch-by-regex a file under active iteration.**
2. **`pkill <script>` kills the shell, NOT its in-flight python child**, which then appended a stale
   row to a truncated results file. Contamination looked legitimate.
3. **`setsid` DOES NOT EXIST on macOS.** I hit this twice — it silently no-ops the launch. Verify a
   background launch with `pgrep`, never with an unconditional `echo`.
4. **Ollama caches prompt KV** — repeated identical runs report fake-fast times (`prompt_s≈0`). Only
   first/uncached runs are honest timings.
5. **Metrics can be gamed**: the 8B once scored perfect recovery AND zero hallucination by *echoing
   the fact sheet verbatim*. Hence the `echo` metric.
6. **Salience must come from conversation PROSE only** — raw counting ranks hook files
   (`context-injector.js` 131×) above real work files. The **whitelist** must come from RAW records
   (incl. tool params) or legitimate paths get flagged as hallucinations.
7. **`$?` after a pipe is the LAST command's status**, and an unquoted `$var` may arrive as ONE arg.
   Two harness artifacts nearly produced a confidently-wrong "verified".
8. Bash 3.2 on macOS; never `set -euo pipefail` in hooks; `/Users/nathanielcannon/bin/tmux` full path.
9. **argv does not identify a process you care about.** A bash `( … ) &` subshell inherits its
   parent's argv, so `pgrep -f <script pattern>` cannot tell a live job from a hung fire-and-forget
   child it detached. Match on a **recorded PID (owner token)**, corroborate with argv against PID
   reuse — never the reverse. Corollary: bash *exec-optimizes* a **single-command** subshell (argv
   IS replaced), so a one-liner repro of this will falsely pass; the actuator's subshells have
   multiple statements, which is why they persist as bash. My first two repro attempts didn't run
   the contrast I thought they did — the real wedged lane was the honest test.
10. **A guard placed behind an unbounded condition is not a guard.** `_worker_alive && return 0`
   above the TTL check made the TTL unreachable. When adding a liveness fast-path, check that the
   timeout below it is still reachable.
11. **A status command that reads its own env lies about the daemon.** `--status` announced
   "GATED (sense-only)" for a supervisor that was firing live, because the plist's env belongs to
   the daemon, not to the shell asking. Daemons must publish their effective config.
12. **Extracting embedded code to a file to test it DELETES the embedding from the test.**
   `(result.stderr or '').strip()` inside `python3 -c '…'` ends the shell quote early. It passed
   `bash -n`, and passed when I sed-extracted the python to `enrich.py` and ran that — a file has
   no enclosing shell quote to break. Only the real inline run failed, and it failed *quietly*
   (the cause line was simply never written). Test embedded code **in situ**; an extraction tests
   the language, not the embedding. Rule of thumb: never use `'` anywhere inside `sh -c '…'`.
13. **Two writers of the same file with DIFFERENT schemas is not a lock problem.** A mutex
   serialises the writes and still leaves a file that is one schema or the other at random. When
   the payloads are disjoint, the fix is **one writer per file + merge on read**, not locking.
   Detection trick that found it: read the file twice a minute apart and diff the *shape*.
14. **`curl -sf` failure is not "service down".** rc 7 refused / rc 28 timeout / rc 22 HTTP≥400 are
   three different worlds — only the first is down; the other two mean the service is ALIVE. Any
   health probe that reports a boolean has thrown away the only information that makes the alert
   actionable. Keep the rc, and record latency in the alert itself — a health file that is
   overwritten every pass cannot explain an incident 10 minutes later.
16. **Keystrokes are not a message; a TURN is.** `cmd_nudge` logged "sent" on injecting text,
   and a retrier reported `DELIVERED on attempt 10` — while the target's transcript never grew a
   `"type":"user"` record. The text sat unsent in the input box for 30+ minutes, unread, with every
   layer above reporting success. A human line already in the box is enough to cause it. **Verify a
   delivery against the artifact that can FALSIFY it** (a new user record), not against the action
   you performed. Fixed in `69dee87`: rc 4 = UNVERIFIED, distinct from 3 (skipped) and 0.
   Sibling hazard, same function: `clear-input` is required but destructive, and the buffer is not
   always junk — a human's unsent line lives there. Now snapshotted to
   `.claude/logs/nudge-preclear.<key>.txt` first, so a discard is recoverable.
15. **`ls -S | head -1` is not a tie-break.** Equal-size candidates fall back to name order, so
   "largest wins" silently became "alphabetically first wins" — which chose a path derived from a
   legacy symlink. Any "pick the best" one-liner needs its ties decided explicitly.
