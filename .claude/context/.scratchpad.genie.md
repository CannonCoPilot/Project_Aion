## Library access — WORKING, but session-bound

BYU is **OCLC EZproxy with hostname rewriting**, not `login?url=`:
`journals.asm.org` → `journals-asm-org.byu.idm.oclc.org`. Config key
`ezproxy.host_suffix = byu.idm.oclc.org` in `.fulltext_access.json`.

**Refresh + verify before ANY bulk job** (an expired session returns a login
page with **HTTP 200** — `is_login_page()` is the only thing standing between
us and 9,000 saved login forms):

```
.venv/bin/python scripts/chrome_cookies.py --domains byu.edu oclc.org asm.org \
    duosecurity.com springer.com wiley.com proquest.com --out ~/.byu_cookies.txt
.venv/bin/python scripts/fulltext_acquire.py --probe    # want ENTITLED
```

Three traps, each silent, do not "fix" them back:
- **`expires=0` session cookies**: Python reads epoch-expired and won't send;
  curl sends always. The EZproxy cookie is this kind. Normalised in `Fetcher`.
  Symptom: **curl works, tool bounces to SSO.**
- **`#HttpOnly_` prefix**: curl understands it, Python treats the line as a
  comment. `chrome_cookies.py` deliberately omits it.
- **doi.org returns `http://`** for old records and the proxy 404s — scheme is
  forced to https in `_decorate`. This recovered 5 dead tier-1 DOIs.

Cookies die when **Chrome quits**; EZproxy expires on idle but any proxied
request resets it. Wiley = HTTP 400, needs a `Wiley-TDM-Client-Token`, not
cookies. **Ask about a full-tunnel VPN** — it removes cookies entirely.
