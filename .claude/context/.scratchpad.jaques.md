## The hardening (User chose option 2: make it harder, not relabel)

Both agents beat v1 by going straight to PC adjustment, so the two new confounders are ones PCs

   call_rate 0.964 (above the 0.95 floor, so a single-number filter passes it) with case/control
   missingness differing at p=2.14e-07. New QC columns `call_rate_cases`, `call_rate_controls`,
   `missing_diff_p`; new cause `differential_missingness`.
3. GC dual constraint still holds: λ needed 3.26 > λ allowed 1.29 (after the CM-005 retune).

**Mechanism lessons — do NOT re-derive these, both cost real time:**
- **Pairs of relatives do almost nothing.** Variance inflation needs clusters; families of 9
  contribute ~1 independent observation while carrying 9 rows.
- **Selecting founders on case status is the WRONG mechanism** even though it makes a strong
  artifact: the survivor of each pruned pair is still biased, so pruning would not clear it.
  It works with families because FAMILY_SIZE-1 of every FAMILY_SIZE biased rows are removed.
- Two new baselines, one per trap: `pc_only_unpruned`, `skip_missingness_check`. Each is the
  correct pipeline with exactly one layer removed, and each fails on its own trap test. That
  is what proves the layer is graded.

## THE BIG LESSON: fairness of grading (a whole layer, all found by real agents)

**Rule: anything a verifier compares strictly must be decided by the analysis, not by a
defensible implementation difference.** Memory: [[feedback-declare-output-vocabulary]].

| graded thing | failure mode | fix |
|---|---|---|
| `qc_status`, `exclusion_reason` vocab | guess-the-word (gpt-5.5 wrote `fail`, Opus wrote `hwe_p<1e-6`) | vocabularies declared in study_design.json |
| numeric cells on excluded rows | undeclared convention | schema note; empty accepted |
| relatedness counts | estimator-dependent | KING-robust estimator AND the sample_id tie-break pre-registered; counts graded with tolerance |
| statuses near a p cut | model-choice-dependent | `acceptable_statuses` set, 5x window, 9 of 80 cells |
| exclusion reasons near a QC floor | computation-dependent | `acceptable_exclusion_reasons`, 4 cells |

`BOUNDARY_FACTOR = 5.0` (not 3): PC count alone moves p more than 3x, and the plan leaves that
open. Traps are orders of magnitude from their cuts, so this costs no discrimination — but that
claim is what regate5's Gate 2 is verifying.

**`scratch/frontier-cal/margin_audit.py`** reports every graded decision's distance from the cut
that decides it, skipping cells the key already tolerates. **Currently exits 0 = clean.** Re-run
it after ANY generator change; a non-empty report is a coin-flip cell waiting to be found by an
agent. (Its own first version had a bug: ratio test flagged call_rate 1.0 vs a 0.95 floor as
"near" — use absolute distance for bounded quantities.)
