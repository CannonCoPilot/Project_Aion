## Problem Identification

The issue was identified as the `_resolve` function in `suggest.py` selecting the first candidate printing without verifying if it had a valid USD price. This led to cards being displayed with "$0.00" when the first candidate was a foil-only printing or lacked a USD price. The fix required selecting the cheapest printing with a valid USD price, falling back to foil if necessary, and displaying "—" if no printing had a price.

## Solution Implementation

1. **Fixing the Price Resolution Logic**: The `_resolve` function was modified to select the cheapest printing with a valid USD price, following the same fallback pattern used elsewhere in the CLI. This ensured that the cheapest non-foil USD price was selected first, followed by the cheapest foil price if no non-foil price was available.

2. **Updating Display Logic**: The display logic in `cli.py` and the web output was updated to handle `None` values properly, displaying an em dash ("—") instead of "$0.00" for unpriced cards. A helper function `_price_cell` was introduced in `cli.py` to deduplicate the price formatting logic.

3. **Testing and Verification**: The fix was verified by running the deck suggest command on an actual deck and confirming that the price display was corrected. The test suite was updated to include tests for the new logic, ensuring that the cheapest printing was selected and that `None` prices were handled correctly.

## Additional Defects Identified

1. **Casual Format Filtering Issue**: The `deck.format` defaulting to "casual" caused all candidates to be rejected due to Scryfall not recognizing "casual" as a valid format. This was fixed by modifying the `_playable` function to skip legality checks for the "casual" format, aligning it with the behavior in `printings.py`.
