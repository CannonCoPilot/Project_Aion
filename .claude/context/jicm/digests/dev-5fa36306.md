## The real find: the unpushed-commit rule has been dead twice

This morning I replaced the dead `origin/Project_Aion..HEAD` with `@{upstream}..HEAD`. **`@{upstream}` fataled too** — `main` had no tracking branch configured at all, even though `origin/main` is a valid ref. I swapped one non-existent ref for another, and `wc -l` turned the empty output into a confident `0` both times.

`★ Insight ─────────────────────────────────────`
Both bugs survived because **the broken output is identical to the healthy output**. `0 unpushed` is what a clean repo looks like, so no reading of the count can distinguish a working rule from a dead one. My own note even said "the proof is `rev-parse`, not the count" — and I ran `rev-parse` on the revspec I was *replacing*, never on the replacement. Verifying the thing you're removing is not verifying the thing you're adding.
`─────────────────────────────────────────────────`

**Fixed in `d72343f`.** `get_unpushed` resolves the base ref explicitly (configured upstream, else `origin/<branch>`) and returns the string `na` when neither exists. The sentinel is a string deliberately, so it sits outside the measurement's value domain — a numeric sentinel collided with real negative lag in `_state_lag_sec` once already. Virgil now says "cannot measure", ranked below real conditions so it never masks one, instead of "All systems nominal".

Tested 6/6 against real throwaway repos, running the shipped function extracted verbatim rather than a copy, with three must-fire cases. I also set the missing tracking config, but that's machine-local — a fresh clone would reintroduce the silent zero, so the code hardening is the actual fix.
