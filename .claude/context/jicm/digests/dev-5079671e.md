## Chrome-in-Claude Investigation

I investigated the Chrome-in-Claude issue and found that the denial error was not related to the model being used. The error message interpolated the model name into a generic "classifier backend unavailable" template. I tested this by running a disposable session with a different model and found the same error message with the new model name.

I discovered that the Chrome integration put the session in auto mode regardless of the project's `bypassPermissions` setting. The key flag was `tengu_cowork_auto_mode_include_allowed_write_mcp = true`, which meant that explicitly-allowed write MCP tools were included in auto mode. However, there were currently zero Chrome allow rules, so this path had never been exercised.

I found that the `/permissions` dialog revealed a genuine recovery path when the classifier was unavailable, allowing manual approval of the denied command. However, manual approval did not unblock the call, as the classifier was consulted on every call with no override once auto mode was on.
