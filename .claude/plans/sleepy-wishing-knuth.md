# Plan — Bible Gold-Set Standard: full parity + operational readiness

## Context

We have two families of "gold" artifacts in Palimpsest (`core/tests/fixtures/gold/`):

- **Annotation golds** (`work-N.json`, 20 works) — sparse, anchor-based detector-scoring ground truth. Consumed by the machine-local, human-run tools `gold_verify.py` (consistency), `gold_ratify.py` (independent-recount accuracy), `a3_score.py` (detector recall).
- **Reconstruction maps** (`maps/work-N.map.json`, 36 works) — dense, exact char-span masking layouts + `reference_sha256`. Applied directly via `server._apply_gold_map`. 16 are **map-only** (idx 108 + the marker-Bible program 201–219); these have no annotation gold.

The phrase "Gold Set" is currently overloaded and the guarantee is asymmetric: the 20 dual works get 4 verification lenses; the 16 map-only Bibles get 1 (the hermetic `test_gold_maps.py` shipped in `1959f8c`). Sir has redefined the bar: **a text is Gold Set Standard only if it is (1) confirmed complete/accurate/precise in masking, (2) at full validation parity with other Gold-Set texts of its kind, and (3) confirmed operationally ready for import through ALL Palimpsest paths — CLI, API, UI.**

This plan brings all 19 Bibles to that bar and codifies the standard so it can't silently drift. Scope now: **Bibles only** (per Sir). Non-Bible golds are re-audited in a later pass (Phase 8) and keep "Gold Set" status only if ≥2 works of their kind already meet the bar.

Copyright policy (Sir): we have full **use** rights (masks/annotations/derivatives are committable) but will not **distribute** source binaries. "Preserve, don't push" — source epub/pdf/txt stay local (gitignored), with a committed fingerprint audit trail.

## The two gold kinds (codified, dissolves the fork)

One standard, two artifact kinds keyed to detection difficulty:
- **Reconstruction gold (map) — universal.** Every Gold-Set work has a CI-verified map. This *is* the masking.
- **Detection gold (annotation) — conditional.** Required only where structure must be inferred by the detector (implicit-structure epub/pdf). Self-describing marker scripture is exempt **by design** — map-only is *complete*, not lesser.

Rigor parity for marker Bibles is reached not by bolting on annotation golds (theater for self-marked text) but by adding an **independent canonical accuracy check** they currently lack.

## Implementation

### Phase 1 — Spec doc (codify the standard)
New: `docs/development/gold-set-standard.md`. Defines the two kinds, the 3-criteria bar, the per-kind parity rule, and the audit/registry model. Add a one-line pointer from the collections-tier build journal. This is the anti-drift anchor everything else references.

### Phase 2 — Canonical versification oracle (the rigor elevation)
New data: `core/tests/fixtures/gold/canon_chapters.json` — per-book **chapter counts** for the 66-book Protestant core + deuterocanon/apocrypha books that appear in our Bibles (Tobit, Judith, Wisdom, Sirach, Baruch, 1–2 Maccabees, etc.). Chapter divisions are stable across translations (Langton, ~1227), so this is a hand-verifiable, defensible oracle. Verse counts vary by tradition → recorded, not hard-gated.

New verifier: extend `test_gold_maps.py` (or a sibling `test_gold_canon.py`) with a per-Bible test that:
- resolves each map's `book` sections to canonical ids by reusing `canon._normalize` / `book_division` (`core/palimpsest/canon.py:94,127`),
- counts `chapter` sections per book from the frozen map,
- asserts per-book chapter count == the oracle (skips books not in the oracle, e.g. Wessex Old-English fragments; records verse totals).

This gives map-only Bibles an *independent* accuracy guarantee stronger than the annotation works' human eyeball — closing the rigor gap by exceeding it. Full-canon Bibles (66-book: 201/202/208/209/210/212/213/216/218) validate fully; variant/partial/NT-only (203/211/214/215/217/219/108 + Catholic 5/100) validate the books they contain and record the versification tradition.

### Phase 3 — `sources.manifest.json` (audit trail + registry + scorecard), Bibles-first
New: `core/tests/fixtures/gold/sources.manifest.json`. One record per Bible source:
`{ id, translation, spelling, typeset, file_type, source_origin, source_filename, source_sha256 (binary, preserved-local), reference_sha256 (produced text), kind (marker/detector/bespoke), gold_artifacts (map path, annotation path|null), canon_shape, validated: {cli, api, ui} }`.

Doubles as: the **audit trail** (fingerprints ship, binaries don't), the **corpus registry** (replaces the annotation-only `GOLD_IDXS` glob as the enumeration source — see `gen_gold_maps.py:34`), and the **Gold-Set scorecard** (the `validated` block records each Bible's operational-readiness state).

New tool: `core/tests/fixtures/gold/mask_engine/verify_sources.py` — hashes the local (gitignored) source corpus and checks against the manifest's `source_sha256`, so "preserve, don't push" is enforceable by anyone holding the corpus. A hermetic test asserts every Bible map has a manifest entry (registry completeness) without needing the binaries.

### Phase 4 — API: first-class gold endpoints

- `POST /api/gold/{idx}/apply` — thin wrapper over the existing `_apply_gold_map` path (`server.py:623`) + `/api/import/local` (`server.py:1914`) so the UI/CLI apply a stored gold by id.
